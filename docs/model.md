# Правила модели

## Расписание

Строится на четверть, детерминированно по `seed`.

1. Для каждого класса на каждую неделю составляется список часов по предметам
   из учебного плана.
2. Свободные слоты («окна») выбираются по `seed` отдельно для каждой параллели
   и недели — у параллельных классов сетка совпадает, поэтому объединение
   классов вообще возможно.
3. Слоты заполняются по порядку; предмет выбирается по остатку часов, с
   приоритетом предметов, которых в этот день ещё не было.
4. Учитель выбирается только квалифицированный, свободный в это время, с
   нагрузкой ниже нормы; при равенстве — по наименьшей нагрузке, затем по id.
5. Помещение выбирается с достаточной вместимостью; для физкультуры,
   информатики, химии, физики и технологии — только профильное.
6. Если слот не удалось заполнить, он попадает в «повтор»; после обхода всех
   слотов остаток часов раскладывается в окна.

Инварианты (закреплены тестами): весь учебный план размещён, `unplaced = 0`,
нет двойных назначений учителя и помещения, вместимость соблюдена, недельная
нагрузка не выше нормы.

## Событие и решения

Событие сценария: учителя нет на указанных неделях, резерв может быть изменён.
Затронутые занятия — занятия этих учителей в эти недели.

| Действие | Что делает | Чем платит |
|---|---|---|
| `reassign` | занятие ведёт другой специалист, класс остаётся в своём кабинете | переработкой, если норма превышена |
| `substitute` | внешний преподаватель (`SUB:<id>`) | ставкой замены за час |
| `postpone` | занятие переезжает в свободный слот той же или следующей недели | ничем в этой версии (см. границы) |
| `merge` | два класса параллели сидят вместе; при нехватке места оба переезжают | переработкой учителя-хозяина |
| `cancel` | занятие не проводится | непроведённым занятием |

Политика `mixed` пробует по порядку: перераспределение → объединение → перенос
→ замена → отмена. Политика `manual` применяет ровно то, что выбрал человек,
включая совет помощника, — и тогда ограничения проверяются на этом решении.

## Показатели

```
непроведённые занятия = число занятий со статусом missed
покрытие, %           = проведённые / запланированные × 100
дополнительная нагрузка = Σ по (учитель, неделя) max(0, часы − норма)
разброс нагрузки      = стандартное отклонение переработки по учителям
расходы               = замены × ставка замены + переработка × ставка × (коэф − 1)
```

## Нарушения (коды)

| Код | Уровень | Когда |
|---|---|---|
| `TEACHER_CLASH` | ошибка | учитель в двух местах одновременно |
| `ROOM_CLASH` | ошибка | помещение занято дважды |
| `ROOM_CAPACITY` | ошибка | класс не помещается |
| `QUALIFICATION` | ошибка | предмет ведёт неспециалист |
| `UNAVAILABLE` | ошибка | учителя нет в паспорте или он недоступен в это время |
| `OVERLOAD` | предупреждение | нагрузка выше нормы (переработка оплачивается) |
| `BUDGET` | ошибка | расходы выше резерва |

Объединённое занятие не занимает отдельного учителя и помещения: два класса
сидят вместе, это одна пара, а не две.

## Идентификатор прогона

```
runId = sha256( версия движка + seed + сценарий + политика + решения + отпечаток паспорта )
```

Один и тот же вход — один и тот же `runId`. Прогон можно выгрузить в JSON
вместе с журналом и проверить через год.

## Цифровой помощник

Рекомендации в прототипе подготовлены заранее — так и записано в концепции.
Проверка идёт по актуальному паспорту и текущему расписанию, а не по снимку:

- учителя нет в актуальном паспорте → `UNAVAILABLE`;
- учитель недоступен или уже занят → `UNAVAILABLE` / `TEACHER_CLASH`;
- переработка считается накопительно по всем занятиям рекомендации
  (иначе «+1 час» выглядит безобидно пятнадцать раз подряд) → `OVERLOAD`.

Сценарий 3 демонстрирует ровно это: совет от 14.11 предлагает учителя `T-999`,
которого в паспорте на 16.11 нет.

## Границы версии 0.1

- перенос не имеет цены: программа, окна и последовательность темы не
  моделируются — это следующая задача, а не скрытый коэффициент;
- помещения проверяются по вместимости и типу, но не по оборудованию;
- нормы нагрузки и ставки — параметры, которые подтверждает школа;
- прогноз не сверен с фактом: для этого нужны данные реальной четверти.
