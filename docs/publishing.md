# Публикация

## Правило

Публикует человек. Агент только собирает и проверяет. Это не формальность:
на сайте университета ошибка видна абитуриенту, а в репозитории на GitHub —
всему интернету.

## Порядок

```bash
node tools/make-demo-data.mjs     # если данные менялись
node --test "tests/*.test.mjs"
node tools/build-dist.mjs
node tools/check-public-data.mjs  # нет ФИО, нет data/real
```

Затем — отдельно, руками:

1. вынести `school-twin` в отдельный репозиторий (или добавить как проект
   GitHub Pages);
2. включить Pages → Source: GitHub Actions;
3. `.github/workflows/pages.yml` соберёт `dist` и выложит;
4. проверить ссылку в браузере и прогнать `tools/e2e.mjs` с
   `TWIN_URL=<адрес>`.

## Что можно публиковать

- демонстрационный паспорт (синтетические данные);
- код движка и интерфейса;
- методику и документацию.

## Что публиковать нельзя

- `data/real/` — реальные данные школы (в `.gitignore`);
- ФИО учителей и учеников — в модели только коды;
- `netlogo/results.csv`, выгрузки прогонов участников;
- ключи, пароли, адреса внутренних сервисов.

Проверка `tools/check-public-data.mjs` ищет шаблон ФИО и наличие запрещённых
каталогов. Она не заменяет внимательность: шаблон ловит не всё.

## Возврат

Сайт статический: откат — предыдущая версия `dist` или предыдущий коммит.
Серверная часть не нужна, поэтому «упавшая база» здесь отсутствует как класс.
